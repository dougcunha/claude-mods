## Respostas

**1. O design está pronto para o checkout?**
Não. Encontrei 3 problemas:
- **Um pedido guarda só 1 SKU.** A tabela `orders` tem 1 coluna `sku`, mas um `Cart` contém muitos itens. Um checkout com 2 itens não cabe nessa tabela.
- **O dinheiro usa `number` de ponto flutuante.** Somas como `0.1 + 0.2` dão `0.30000000000000004`. O valor de `Cart.total()` pode ficar diferente da coluna `orders.total`.
- **Não há testes nem código que chame `discount`.** O `Cart` não aplica desconto, então a regra de preço não chega ao checkout.

**2. Por que `total` não arredonda o resultado?**
O código não tem regra de arredondamento: `total()` só soma `item.price` (`src/cart.ts:10-12`). O `discount()` também devolve um valor sem arredondamento, por exemplo `9.99 * 0.85 = 8.4915`. Para o checkout, recomendo guardar os preços em centavos, como inteiros. Assim a soma é exata e só o desconto precisa de arredondamento.

**3. A coluna `sku` precisa de um índice?**
Hoje não. Nenhuma consulta filtra pedidos por `sku`. Mas, se `sku` virar chave estrangeira (pedido 6), crie o índice. O PostgreSQL não cria índice automaticamente em chave estrangeira. Sem índice, um `DELETE` ou `UPDATE` em `items` faz uma varredura completa em `orders`.

## Plano para os pedidos de mudança

**A. Mover a regra de desconto para uma classe `Pricing`** (`src/pricing.ts`)
1. Criar `export class Pricing` com o método `discount(item, percent)`.
2. Validar `percent` entre 0 e 100.
3. Remover a função `discount` solta. Nenhum arquivo chama essa função, então não há chamadas para atualizar.

**B. Usar uma interface no lugar de `Item` em `Cart`** (`src/item.ts`, `src/cart.ts`)
1. Em `src/item.ts`, criar `export interface Priced { readonly sku: string; readonly price: number }`.
2. Fazer `Item` declarar `implements Priced`.
3. Em `src/cart.ts`, trocar `Item` por `Priced` no campo `items` e no método `add`.

A relação no diagrama passa a ser uma dependência de `Cart` com `Priced`. O nome "composição" estava errado: o `Cart` recebe os itens, mas não cria esses itens.

**C. Tornar `sku` uma chave estrangeira para a tabela `items`** (`db/`)
1. Criar a tabela `items` com `sku TEXT PRIMARY KEY` e `price NUMERIC NOT NULL`.
2. Adicionar `REFERENCES items(sku)` à coluna `orders.sku`.
3. Criar `CREATE INDEX orders_sku_idx ON orders(sku)`.
